# 第 7 章：记忆（Checkpointer）与人在回路（LangGraph）

> 练习：`exercises/ch07_memory_hitl.py`　验证：`uv run python check.py 7`

## 1. 关键概念

### 1.1 Checkpointer：给图加上“存档”

编译时传入 checkpointer，图在**每一步之后**都会把状态保存为一个快照（checkpoint）：

```python
from langgraph.checkpoint.memory import InMemorySaver

graph = builder.compile(checkpointer=InMemorySaver())
```

- `InMemorySaver`：保存在内存里，程序退出就没了，适合学习和测试
- 生产环境：`langgraph-checkpoint-sqlite`（SqliteSaver）、`langgraph-checkpoint-postgres`（PostgresSaver）等

### 1.2 thread_id：区分会话

存档按 `thread_id` 分组。调用时通过 config 指定：

```python
config = {"configurable": {"thread_id": "user-42"}}
graph.invoke({"messages": [("human", "我喜欢猫")]}, config)
graph.invoke({"messages": [("human", "我喜欢什么？")]}, config)   # 自动接上之前的历史
graph.invoke({"messages": [("human", "我喜欢什么？")]}, {"configurable": {"thread_id": "other"}})  # 全新会话
```

有了 checkpointer，**每次只需要传入新消息**，`add_messages` reducer 会把它追加到存档的历史后面。

### 1.3 读取状态

```python
snapshot = graph.get_state(config)
snapshot.values     # 当前状态字典
snapshot.next       # 接下来要执行的节点（图暂停时非空）
list(graph.get_state_history(config))   # 所有历史快照（可用于“时间旅行”调试）
```

### 1.4 interrupt：暂停等待人类

在节点中调用 `interrupt(payload)`，图会在此暂停，并把 `payload` 交给调用方：

```python
from langgraph.types import interrupt, Command

def confirm_delete(state):
    answer = interrupt({"question": f"确定删除 {state['file']} 吗？"})
    return {"deleted": answer == "yes"}

result = graph.invoke({"file": "a.txt"}, config)
result["__interrupt__"]      # [Interrupt(value={'question': '确定删除 a.txt 吗？'}, ...)]

graph.invoke(Command(resume="yes"), config)   # 恢复执行
```

恢复时的执行细节（务必理解）：

1. 被中断的节点会**从头重新执行**
2. 这一次 `interrupt(...)` 不再暂停，而是直接返回 `Command(resume=...)` 中的值
3. 因此 `interrupt` 之前的代码会执行两次 —— 不要在 interrupt 之前放有副作用的操作（如真正扣款）

interrupt 依赖 checkpointer 保存暂停时的现场，所以**必须**配置 checkpointer 和 thread_id。

### 1.5 Command：更新状态 + 决定去向

节点可以返回 `Command`，同时完成“更新状态”和“跳转”，不需要再写条件边：

```python
def review(state) -> Command:
    if state["score"] > 80:
        return Command(goto="publish", update={"status": "ok"})
    return Command(goto=END, update={"status": "rejected"})

builder.add_node("review", review, destinations=("publish", END))  # 声明可能的去向，便于画图
```

`Command` 有两种用途，不要混淆：
- **节点返回** `Command(goto=..., update=...)`：控制流转
- **调用方传入** `graph.invoke(Command(resume=...))`：恢复被 interrupt 暂停的图

## 2. 使用场景

- **记忆**：多轮聊天机器人、长任务断点续跑、多用户隔离
- **人在回路**：敏感操作审批（转账、发邮件、删除数据）、让人修改模型生成的内容、在 Agent 不确定时向人提问
